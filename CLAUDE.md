# Alexandria hub

Read README.md first. A Starlight site for the office's Alexandria tools; the audience is designers, not developers.

- Never edit what `tools/sync.py` writes (listed in the README): change it in `../alexandria_phoenix` and run the sync.
- One style for everything: `src/styles/theme.css`. Clean and simple: greys, one blue (for buttons, the Beta tag and what's under the pointer only: a tool card's edge and halo, a sidebar entry; the Alpha tag is grey), and colour otherwise only where it codes something (the toolbar groups in the guides, the state tags in a management table). The look is a drawing sheet's (Felipe, 2026-11-23, from reference sites: minimal, but still expressive, and never so spare that the team can't find a tool): hairlines and joined cells instead of separate rounded boxes, every small label in mono capitals, a sheet letter in a solid chip, a ticked ruler under a section's name and a page's title, line glyphs. Every name and link stays in plain sight. No other decoration, display type or effects. Reuse its tokens and `ax-` parts; guides use the quick guides' `qg-` classes from `src/styles/guides.css`. The Material Estimator (in `../alexandria_office`) uses the same values.
- Keep every page `noindex`, and keep the hub out of the public docs site and the portfolio until it's secured.
- The release zip is uploaded to GitHub releases, never committed (`release/` is ignored).
- Write plainly and briefly, for someone opening Rhino, not reading code. On user-facing pages (home, the tool pages, First Day, Download) the drawings carry it: labels and fragments joined with ` · `, not sentences or paragraphs (Felipe, 2026-11-23). The one exception is the home page's About, a few light sentences on what Alexandria is for. The detail goes in the tool's quick guide, which is a drawing too: the tool's screen with numbered dots that open on a click, and a few steps (`src/guides/vectorizer.html` is the pattern). One line per dot, each fact once, no tips lists and no bold lead-ins (Felipe, 2026-11-23). A tool card on the home page is sheet number, drawing, name and links only, and the home page draws its cards and its index strip from `src/tools.ts`, so a new tool goes there; a tool on its category page is a `ToolSheet` (drawing, a few facts, links).
- No note at the top of a page, and none under a table or at the end (Felipe, 2026-11-25: "every page gets one of these stupid little notes at the top"). A page starts with its first heading, drawing, table or button. No line saying what the page or tool is, that it needs nothing installed, that it updates itself, or where else to look. If the page works without a line, the line goes. The home page's About is the one exception.
- The sidebar holds sections, never a single tool, guide, supplier or file: add a new one to its section's page, and to `src/nav.ts` (README, The Sidebar).
